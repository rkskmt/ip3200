オープンデータか

オープンデータとは

  • 政府・自治体が 誰でも自由に使える形式 で公開するデータ
  • 商用・非商用問わず 二次利用可能
  • 機械可読（CSV, JSON, API）で提供

意義

  • 透明性：行政の活動を市民が検証できる
  • イノベーション：民間がデータを活用してサービス開発
  • 効率化：データに基づく政策立案（EBPM: Evidence-Based Policy Making）

「オープン」の源流

書影: O’Reilly Media, via Wikipedia

全文を読む（山形浩生 訳）

  • 「オープン」の源流は ソフトウェア
    • オープンソース：コードを公開し、誰でも使える・直せるようにする
  • 古典『伽藍とバザール』（The Cathedral and the Bazaar、1999）
    • 伽藍（＝大聖堂）方式：専門家だけで 閉じて 作る
    • バザール方式：全部公開して、大勢で作る
    • 主張は バザールの勝ち（証拠は Linux）
  • オープンデータは、この「オープン」を 行政データ に広げたもの

配っても、減らない

  • 「魔法のおなべ」（The Magic Cauldron、全文）は、オープンソースの 経済学

問い

コードを タダで配ったら、作った人はどうやって食べていく？

  • カギは 非競合性（non-rivalry）— パンは食べればなくなるが、コードは コピーしても減らない
    • 使う人・直す人が増えるほど改良が戻ってきて、鍋の中身はむしろ増える
  • 売り物は別に作れる：サポート、ハードウェア、ブランド、コンテンツ
  • データも非競合 — 配っても都のデータは減らず、使われた分だけ価値が生まれる

東京都オープンデータAPI

概要

  • 東京都オープンデータカタログサイト の一部データをAPI提供
  • ユーザ登録不要 — 誰でもすぐに利用可能
  • 掲載データ約54,000件のうち、CSV約35,000件がAPI対応
項目 内容
認証 不要
レート制限 明示なし（常識的な範囲で）
データ形式 JSON / XML
CORS 対応済み

Wikipedia APIとの違い

Wikipedia API 東京都API
HTTPメソッド GET POST
User-Agent 必須 不要
データ内容 百科事典・統計 行政・地理・施設
更新頻度 リアルタイム〜日次 不定期（年次も多い）

重要：今回はGETではなくPOST

  • Wikipedia API は requests.get()
  • 東京都API は requests.post()

東京都オープンデータAPIの構造

基本URL

https://service.api.metro.tokyo.lg.jp/api/{apiId}/{format}
  • {apiId} — データセットごとに異なるID
  • {format} — json または xml

例：東京都人口の推移（JSON）

https://service.api.metro.tokyo.lg.jp/api/t000003d2000000236-c054eb26d9e9721642bef78c7c717e76-0/json

APIのIDを探す

  • API検索ページ でキーワード検索
  • 欲しいデータの apiId をコピーして使う

探し方のコツ

  • 「避難所」「駐輪場」「人口」などキーワードで検索
  • 区市町村名で絞り込み可能
  • 詳細ページで apiId と列名を確認

ただし、リンク切れや内容がないことも多いため確認が必要

基本的な使い方

まず、何もなしで呼ぶ

  • パラメータも条件も付けず、空のオブジェクト 「{}」 を POSTする
    • GETではない
import requests

api_id = "t000003d2000000236-c054eb26d9e9721642bef78c7c717e76-0"
url = f"https://service.api.metro.tokyo.lg.jp/api/{api_id}/json"

response = requests.post(url, json={})
data = response.json()

print(data)
{'total': 152, 'subtotal': 100, 'limit': None, 'offset': None, 'metadata': {'apiId': 't000003d2000000236-c054eb26d9e9721642bef78c7c717e76-0', 'title': '人口の動き（令和５年中） 参考表４　人口の推移（東京都、全国）(明治５～令和５年)', 'datasetId': 't000003d2000000236', ...（2万文字以上つづく）

json={} は必須

  • 空のJSONボディ送信が必須（東京都APIの仕様）
  • 仮に省略すると 415（Unsupported Media Type）が返ってくる

Pandasなので絞り込みも楽

  • 列 の絞り込み（西暦（年次）など）
    • DFやSeriesなどのサブセットにする
  • 行 の絞り込み（期間指定など）
    • 条件にあう行の抽出
# 列：使う列だけ選ぶ
pop = df[["西暦（年次）", "東京都／人口"]]

# 行：受け取ってから、条件抽出で絞る
recent = df[df["西暦（年次）"] >= 1950]

  • 実は、bodyに column というキーでPOSTすれば絞られた状態で戻る — 必要な列だけ受け取れる
body = {"column": ["西暦（年次）", "東京都／人口"]}
response = requests.post(url, json=body)

import requests

どんな形で増えた？

  • 最小 859,345人（1872年）から最大 11,521,226人（1971年）まで、100個の値が並んでいる
  • データの可視化の大原則 — Always plot your data first.

1945年の東京で何が起きた？ いなくなった人は、いつ戻った？

  • 空襲と疎開 — 戦争末期、東京から人が離れた
  • 戻りも速い：1946年に +69万人、1947年に +82万人。5年後の1950年には600万人台まで回復
  • 歴史の教科書の出来事が、数列にそのまま刻まれている

演習：東京一極集中はいつから？

人口データの 「東京都／対全国比(%)」 を折れ線グラフに描き、日本の人口の 1割 を最初に超えた年を答えよ。

  1. 人口データを取得し、DataFrameにして列名を確認
  2. 対全国比の値は文字列 — .astype(float) で数値化（増減率のときと同じ下ごしらえ）
  3. 折れ線グラフに描き、10%を最初に超えた年を確認
解答例を見る 
import requests
import pandas as pd
import matplotlib.pyplot as plt
import japanize_matplotlib

api_id = "t000003d2000000236-c054eb26d9e9721642bef78c7c717e76-0"
url = f"https://service.api.metro.tokyo.lg.jp/api/{api_id}/json"

response = requests.post(url, json={})
data = response.json()

df = pd.DataFrame(data["hits"])
shares = df["東京都／対全国比(%)"].astype(float)

over10 = df[shares >= 10]
print(f"最初に10%を超えた年: {over10['西暦（年次）'].min()}年")

plt.plot(df["西暦（年次）"], shares)
plt.title("Tokyo Share of Japan Population")
plt.xlabel("Year")
plt.ylabel("Share (%)")
plt.grid(True, linestyle="--", alpha=0.5)
plt.show()

一極集中は戦前に始まっていた

  • 1872年は 2.5%（40人に1人）
  • 最初に10%を超えたのは 1940年
    • 戦前にすでに「1割が東京」だった
  • 1945年に 4.8% へ急落（人口の谷と同じ理由）し、1959年に再び10%へ

演習：2つのデータセットを比較

異なる2つのデータセット（例：2つの区の避難所、戦前と戦後の人口）を取得し、件数や統計量を比較して表示せよ。

  • （発展）同じグラフに重ねて描画
解答例を見る（戦前と戦後の人口を比較する例） 
import requests
import pandas as pd

api_id = "t000003d2000000236-c054eb26d9e9721642bef78c7c717e76-0"
url = f"https://service.api.metro.tokyo.lg.jp/api/{api_id}/json"

response = requests.post(url, json={})
data = response.json()

df = pd.DataFrame(data["hits"])
prewar = df[df["西暦（年次）"] <= 1944]
postwar = df[df["西暦（年次）"] >= 1946]

print(f"戦前（〜1944）: {len(prewar)}年分 平均 {prewar['東京都／人口'].mean():,.0f}人")
print(f"戦後（1946〜）: {len(postwar)}年分 平均 {postwar['東京都／人口'].mean():,.0f}人")

（参考）よく見るとhits list長とtotalが違う

  • 152年分あるのに、100件しか届いていない
    • 1回に届く件数は、指定しないと先頭100件まで

（参考）URLの後ろに ?limit=200 を付ければ全件届く

response = requests.post(url + "?limit=200", json={})   # limitはデフォルト100・最大1000
data = response.json()

print(len(data["hits"]))
152

（参考）1,000件を超えたら — ページング

  • 1,000件を超えるデータは、limit を最大にしても1回では取り切れない
  • このとき、東京都APIでは取得開始位置 offset をずらしながら、同じリクエストを繰り返すことになっている
    • このようなデータの応答や表示の分割を ページング（paging）という
  • たとえば total: 2500 のデータなら3回に分ければとれる：
呼び出し URLに付ける 届く範囲
1回目 ?limit=1000&offset=0 1〜1000件目
2回目 ?limit=1000&offset=1000 1001〜2000件目
3回目 ?limit=1000&offset=2000 2001〜2500件目
  • 毎回の hits をつなげば全件そろう
  • Webサービスの「次のページ」「もっと見る」も、裏側はこの仕組み

（参考）全件取って、足元を拡大する

  • 本編のグラフは1971年で切れていた — ?limit=200 で 152年全部 を取り直すと、2023年まで伸びる
  • 「七夕」の8月29日を見つけたときと同じ手 — 軸の範囲を絞って足元を拡大 する
    • グラフのコードに plt.xlim(2018, 2024) と plt.ylim(13.85, 14.15) を足すだけ
