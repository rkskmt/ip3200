事件：関数に渡しただけなのに

成績データの「2倍にしたコピー」を作ろうとした。

def double_all(data):
    for i in range(len(data)):
        data[i] = data[i] * 2
    return data

scores = [10, 20, 30]
result = double_all(scores)
print(result)  # [20, 40, 60] ← 期待どおり
print(scores)  # [20, 40, 60] ← ！？ 元データまで壊れた
  • scores には一度も代入していないのに、元の成績が消えた

今回のゴール

この回が終わる頃には、この事故を図1枚で説明でき、1行で防げるようになる。

リテラル（値）

  • 事故の正体を突き止めるために、敢えて「変数と代入」をメモリモデルからおさらいする
  • Pythonでは値を直接コードに書ける
    • 値はそれだけで評価できる（エラーにならない）
    • 変数や関数なしで、その行に書くだけで意味を持つ
1
"1"
[1, 2, 3]
True
1.0

メモリ上での記述

上記の値はその行が実行された時に、メモリ上に値として記述される（000001001 のようにメモリ上のスペースを使って記録される）。これらをリテラルと呼ぶ — 直接コード中に記述できる値の表現方法。

変数とは

一方、このように書くとエラーになる。なぜ？

a # NameError: name 'a' is not defined
  • 1 や "1" はリテラル（直接記述できる値）
  • a は値ではなく変数として認識される
  • 変数とは、値をつかんで離さないための「名前」 — 看板が立っている限り値は消えない
  • a はまだどこにも立てていない看板なので、エラーになる

変数の命名規則

変数として認識される単語のルールは以下のとおり。

例外はない — ここは覚えるしかない

  • 文字（a-z, A-Z）またはアンダースコア（_）で始まる
    • つまり数字始まりはダメ（NG例： 3200scores ）
    • 終わるのはOK（例：scores_of_3200）
  • 2文字目以降が文字、数字（0-9）、アンダースコアであること
  • 予約語（if / for / while など）ではないこと
a01    # OK。変数
_aa_aa # OK。変数
1a     # NG。最初が数字
continue # NG。予約語

代入

  • 変数 = リテラル と記述すると「代入」という操作がおこなわれる
    • 左辺は変数
    • 右辺はリテラルかオブジェクト
a = 1234
test_2 = "test2"

箱ではなく「看板」

  • a = 1234 は「a という箱に 1234 が入る」ではない
  • a は 1234 が格納された住所（アドレス）を指す看板になる
  • ただし、アクセス時はその看板自体ではなく住所が指す先にあるリテラルやオブジェクトが返る

変数 = 変数 の代入

  • 変数同士の代入は、左辺に右辺のアドレスを代入する
    • つまり、同じアドレスを指すようになる
a11 = 11
a12 = 12
a11 = a12 # a11とa12は同じアドレスを指す
print(a12) # 12

a11 = 13 # 別の値に変更
print(a11) # 当然13
print(a12) # ??? （同じアドレスを指しているはずだが？）
  • 結果： 12
  • a11 = 13 は「11 だった場所に 13 を書き込む」ではない — 看板の掛け替え
  • 代入 x = ... は常に掛け替え。共有していたのは3行目から5行目までの一瞬だけ
  • 5行目以降、共有していた場所を指すのは a12 だけになる

リストの代入（罠）

数値でやった操作をリストでやると…

odd1 = [1, 3]
odd2 = [5, 7]
odd1 = odd2
odd1[0] = 9
print(odd2) # ???
  • 結果： [9, 7]
  • odd1[0] = 9 は看板の掛け替えではない — 指している先の中身の変更
  • 看板は2枚とも同じリストを指したまま → odd2 から見ても変わる

クイズ：どっちなら odd2 は無事？

ほぼ同じに見える2つのコード。print(odd2) は何と出る？

# A
odd1 = [1, 3]
odd2 = odd1
odd1 = [9, 7]
print(odd2)  # ???
# B
odd1 = [1, 3]
odd2 = odd1
odd1[0] = 9
print(odd2)  # ???
  • A： [1, 3] — odd1 = [9, 7] は看板の掛け替え。odd2 は無傷
  • B： [9, 7] — odd1[0] = 9 は中身の変更。odd2 も巻き込まれる

ルールは2本だけ

操作 何が起きる
ルール1 x = ...（代入） 看板の掛け替え。型に関係なく常に。コピーは起きない
ルール2 x[0] = ... や .append() 指している先の中身を変更。できるのはミュータブルだけ
  • 「リストだけ変な動きをする」のではない — リストは起こせる操作（ルール2）が1つ多いだけ
  • 迷ったら「これは掛け替え？　中身の変更？」と聞けば、すべてのクイズが解ける

ヒント

この2本で、冒頭の事件も説明できる。あと少し道具（id()）を足してから戻ろう。

id() で住所を確認（数値）

id() 関数で、変数が指しているアドレスを調べられる。

a11 = 11
a12 = 12
print(id(a11)) # 2083050422832
print(id(a12)) # 2083050422864
a11 = a12
print(id(a11)) # 2083050422864。a12と同じ場所
a11 = 13
print(id(a11)) # 2083050422896。違う場所を指している。
  • 代入のたびに指す先（アドレス）が変わっている — ルール1（掛け替え）を id() で目撃できる
  • a11 = 13 をしても、11 や 12 の場所は書き換わっていない

豆知識：小さい整数は使い回される

  • CPython は -5〜256 の int をあらかじめ作って使い回す
  • だから x = 11; y = 11 とすると id(x) == id(y) は True になる
  • 「同じ値なら同じ場所を指すことがある」だけで、看板モデル自体は変わらない（高速化のための最適化）

id() で住所を確認（リスト）

リストでは、要素に代入してもアドレスが変わらない。

odd1 = [1, 3]
odd2 = [5, 7]
print(id(odd1)) # 2738928019264
print(id(odd2)) # 2738927989120
odd1 = odd2
print(id(odd1)) # 2738927989120
print(id(odd2)) # 2738927989120
odd1[0] = 9    # odd2ではなくodd1を変更
print(odd1)    # [9, 7]
  • odd1 = odd2 後、両者が同じアドレスを指している
  • だから odd1[0] = 9 が odd2 にも影響する

「同じ場所？」を直接聞く：is 演算子

  • id() == id() を毎回書くのは回りくどい — is で直接聞ける
odd1 = [9, 7]
odd2 = odd1

print(odd1 is odd2)      # True  （同じ場所を指している）
print(odd1 == [9, 7])    # True  （中身が同じ）
print(odd1 is [9, 7])    # False （中身は同じでも別の場所）
  • == は中身の比較、is は場所の比較
  • 「この2枚の看板、同じ実体を指してる？」と聞きたいときは is

ミュータブル / イミュータブル

値（オブジェクト）は2種類に分かれる

  • イミュータブル（immutable）：中身を変更する手段が存在しない型
    • int str bool tuple 等
    • 「変えた」ように見える操作も、すべて新しい値への掛け替え（ルール1）
    • だからアドレスを意識しなくても事故が起きない
  • ミュータブル（mutable）：中身をその場で変更できる型（ルール2が使える）
    • list、dict 等
    • 看板を何枚立てても実体は1つ — 共有に気づかないと事故になる
分類 型
イミュータブル int / float / complex / bool / str / tuple / frozenset / bytes / None
ミュータブル list dict set クラス など

事件の解決：冒頭のコードに戻る

def double_all(data):
    for i in range(len(data)):
        data[i] = data[i] * 2   # ← ルール2：中身の変更！
    return data

scores = [10, 20, 30]
result = double_all(scores)     # ← 関数に渡す＝ data という看板を立てる（ルール1）
print(result)  # [20, 40, 60]
print(scores)  # [20, 40, 60]
  • 関数に渡してもコピーは起きない。引数 data は scores と同じリストを指す看板（ルール1）
  • 中で data[i] = ... と中身を変更したので（ルール2）、scores から見ても壊れていた
  • 約束どおり、図1枚で説明できる：

ミュータブルの罠を回避する：コピー

  • リストを別のアドレスに新たに複製したいときは .copy() を使う
    • 「この場面を残したい」ときにセーブデータを別スロットへコピーするイメージ
    • 単に = で代入しても複製されない（看板が増えるだけ）
  • 冒頭の事故も、渡す側の1行で防げる：
result = double_all(scores.copy())   # 複製を渡す → scores は無傷
odd1 = [1, 3]

# NG: 同じアドレスを共有 → 両方が変わる
odd2 = odd1
odd2[0] = 9
print(odd1)  # [9, 3] ← 意図せず変わってしまう

# OK: .copy() で別アドレスの複製を作る
odd3 = odd1.copy()
odd3[0] = 99
print(odd1)  # [9, 3] ← 変わらない
print(odd3)  # [99, 3]

# （参考）全スライス [:] でも同じ結果
odd4 = odd1[:]
print(id(odd1) == id(odd4))  # False（別アドレス）

まとめ

  • 変数は値そのものではなく、値が置かれたアドレスを指す看板
  • ルール1：代入 x = ... は型に関係なく常に看板の掛け替え。コピーは起きない
  • ルール2：ミュータブル（list / dict 等）だけが中身をその場で変更できる — 共有中の変更は全員に見える
  • イミュータブル（int / str / bool / tuple 等）は中身を変える手段がないので事故が起きない
  • 事故を防ぐには .copy() で別の実体を渡す。確認の道具は id()（住所）と is（同じ場所か）
